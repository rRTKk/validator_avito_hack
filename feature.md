features.py

Файл отвечает за создание признаков для проверки гипотез и подготовку данных для CatBoost. Основная задача — добавить нужные признаки без утечки данных: исторические признаки считаются только на train-части каждого fold-а и затем применяются к validation.

⸻

get_columns(lf)

Возвращает список колонок в Polars LazyFrame.

Нужно, чтобы перед созданием признаков проверять, есть ли нужные колонки в датасете.

⸻

has_columns(lf, columns)

Проверяет, есть ли в датасете все колонки из переданного списка.

Используется перед расчётом признаков, чтобы код не падал, если каких-то колонок нет.

⸻

add_basic_features(lf)

Добавляет базовые признаки, которые можно посчитать из текущей строки без использования таргета.

Создаёт признаки по датам, цене, товару и оплате, например:

* день недели заказа;
* день месяца;
* месяц заказа;
* длина названия товара;
* возраст объявления;
* возраст аккаунта покупателя;
* возраст аккаунта продавца;
* бакет цены;
* разницу между суммой оплаты и ценой заказа.

⸻

add_order_count_features(lf)

Добавляет признаки, связанные с количеством товаров в одном заказе.

Создаёт:

* количество товаров в заказе;
* количество товаров той же категории в заказе;
* количество товаров той же микрокатегории в заказе.

Нужно для проверки гипотезы, что покупатель может заказать несколько похожих товаров и вернуть часть из них.

⸻

build_history_agg(train, keys, prefix)

Считает историческую статистику по заданному ключу на train-данных.

Например, по продавцу, покупателю, категории или городу.

Создаёт:

* количество заказов;
* количество возвратов;
* долю возвратов.

Важно: функция должна использоваться только на train-части, чтобы не было data leakage.

⸻

add_history_features(train, valid, keys, prefix)

Добавляет исторические признаки в train и validation.

Логика:

1. считает статистику только по train;
2. добавляет её в train;
3. добавляет эту же статистику в validation;
4. для train исключает текущую строку из собственной статистики.

Используется для признаков типа:

* seller_return_rate;
* buyer_return_rate;
* category_return_rate;
* city_return_rate.

⸻

add_frequency_features(train, valid, key, prefix)

Считает частотность категории или микрокатегории на train-данных.

Создаёт:

* количество объектов в категории;
* долю категории среди train;
* флаг редкой категории.

Нужно для проверки гипотезы про редкие категории товаров.

⸻

add_buyer_microcat_features(train, valid)

Считает опыт покупателя в конкретной микрокатегории.

Создаёт признаки:

* сколько раз покупатель покупал товары этой микрокатегории;
* сколько было возвратов в этой микрокатегории;
* доля возвратов покупателя в этой микрокатегории;
* первый ли это заказ покупателя в данной микрокатегории.

Нужно для проверки гипотезы, что новые для покупателя категории могут чаще возвращаться.

⸻

add_all_features(train, valid)

Главная функция для добавления всех реализованных признаков.

Последовательно вызывает:

* базовые признаки;
* признаки количества товаров в заказе;
* исторические признаки продавца;
* исторические признаки покупателя;
* исторические признаки категории;
* исторические признаки микрокатегории;
* признаки доставки;
* признаки города;
* признаки редкости категории;
* признаки опыта покупателя в микрокатегории.

Возвращает обновлённые train и valid.

⸻

remove_forbidden_features(features)

Удаляет запрещённые признаки из списка фичей.

Например:

* is_return;
* order_accept_date;
* cancel_date.

Это защита от data leakage, чтобы случайно не передать в модель таргет или признаки, которые напрямую палят ответ.

⸻

get_existing_features(lf, features)

Проверяет, какие признаки из гипотезы реально есть в датасете после feature engineering.

Возвращает:

* существующие признаки;
* отсутствующие признаки.

Нужно, чтобы валидатор мог спокойно работать даже если часть фичей ещё не реализована.

⸻

fill_nulls_for_catboost(lf, features)

Заполняет пропуски в признаках перед передачей в CatBoost.

Правила:

* строковые признаки → "unknown";
* булевы признаки → False;
* числовые признаки → -1.

Это нужно, чтобы модель не падала на пропусках.

⸻

get_categorical_features(lf, features)

Определяет, какие признаки являются категориальными для CatBoost.

В категориальные признаки попадают:

* строковые колонки;
* булевы колонки.

Например:

* city;
* delivery_service;
* category_name;
* microcat_name;
* payment_method_first;
* buyer_gender;
* seller_gender;
* is_pod.

⸻

prepare_train_valid_for_catboost(train, valid, requested_features)

Финальная функция подготовки данных для CatBoost.

Делает полный pipeline:

1. добавляет все необходимые признаки;
2. удаляет запрещённые признаки;
3. оставляет только существующие признаки;
4. заполняет пропуски;
5. определяет категориальные признаки;
6. переводит Polars-таблицы в pandas;
7. возвращает X_train, y_train, X_valid, y_valid, список использованных признаков и список категориальных признаков.

Именно эту функцию будет вызывать валидатор перед обучением модели.
